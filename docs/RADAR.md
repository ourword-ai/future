## 一·A 终端用户闸门（2026-08-03 新增，最高优先，压过 R0/R0a）

用户原话：**「重点是这确实是在解决终端用户需求和痛点，特别是普通用户」**。

**硬门槛**：写条目前先回答——*谁在用？他因此拿到什么成品？* 那个「谁」必须是一个非开发者的身份
（诊所前台、学吉他的人、小生意主、A股散户、想整理衣柜的人…）。答不出、或答案只能是"开发者"
或"某个 AI agent"，**这条直接不要**，星数多高都不要。

**依据**：2026-08-03 全板通标 ✅27 / ❌102。❌ 几乎全是同一形状——终端/CLI 工具、coding agent
周边（harness / 记忆 / 状态栏 / token 计数 / IDE 插件）、给 agent 用的基础设施、开发基础设施、
"某 SaaS 的开源替代"克隆。✅ 全都指得出一个具体普通人。

**唯一例外**：AI 直接产出人能用的成品（设计稿、幻灯片、成片、书稿、一整条需求到交付）——
是成品不是零件。

**与 R0/R0a 的关系**：本闸门在前。先过"说得出人"，再谈兴奋分与「私密数据×本地×新窗口」。
过不了这一关的，兴奋分再高也不写。

## 二、兴奋分 rubric（入选门槛）

- **5** = 朋友追问「怎么做到的？在哪能用？」
- **4** = 眼睛一亮、会转发
- **3** = 有点意思，但不会主动提起
- **2** = 合理但平淡
- **1** = 普通 / 换皮

只有 **≥4** 可入选；先写「给朋友讲的那句话」，再定分。全部 <4 就宁缺毋滥、当轮零新增。

**R0a**：兴奋感须落在「私密数据变活资产 × 本地/隐私 × 新技术窗口」交集上。

**2026-07-30 加分项**：排队证据硬（真人原声多、付费意愿明确、冷启动入口现成）。

## 三、证据取向（2026-07-29 校准，与 STANDARD.md 同一套口味）

「真有用 = 验证过的痛 × 说得出口的缺口 × 我能补的那一刀」

1. **痛要有真人一手证据** —— 有人说愿付钱、有人认真抱怨、有人 fork 回去自己搭。star 数只算注意力，不算需求。
2. **项目新旧不进标准** —— 跑了半年有真用户 > 两天涨一波星。「已经有人做出来了」是需求证据不是窗口关闭；只有当它把普通人那侧也做好了才算关。
3. **缺口要能一句话说清** —— 只有极客用得了／中文本土场景空白／痛点击中但解得不完美。
4. **开发者工具只当能力信号** —— 写条目时必须给出「普通人那侧的机会」。
5. **硬排除（即便需求真）** —— 硬件量产、必须烧钱抢速度、靠 BD/销售开局、纯 B 端内部工具。

## 四、内容校准（2026-07-30 访谈结论）

用户与板面读者是同类人＝「从中找想法去实践去创业的人」。最大卡点是「做出来不知道给谁」，40+ 条 ⭐ 未启动的原因是「在等更兴奋的那条」——所以**「能看见谁在排队等」本身就是兴奋感弹药**。

- 节奏：广度优先、每日 2-3 条精品、宁缺毋滥。
- 每条新条目尽力必附两要素：**真人原声/付费证据**（引原话+链接，找不到就注明「暂无原声」，绝不编造）、**冷启动第一步**（中英各一个具体入口，具体到社区/子版/关键词/评论区）。
- 工作量标注：`2w` / `2m` / `no`。
- 存量补齐：每轮给 3-5 条 ⭐ 存量条目补上述两要素，从最新 ⭐ 批次往回补。

**2026-08-05 X 侦察结论（含一次自我更正，两版都留着）**：

**初版结论是错的，记在这里当教训。** 第一轮我每个社群只抓到 4–9 条就断言「供给侧、原声产出预期为零」。
错因是抓取坏了不是社群不行：X 时间线是虚拟列表，DOM 里同时只有 4–8 条；
而且**后台标签页里 `setInterval` 被 Chrome 节流到接近停摆，纯 JS 自滚根本不前进**。
用户当场质疑「不可能没有需求侧」，重抓后证明用户是对的。**以后凡是拿 <30 条样本下的源判断，一律不算数。**

**正确抓法**：必须用 `computer{scroll}`（真实输入事件，不被节流），
每滚 `scroll_amount:4, repeat:2` 就跑一次 JS 累积去重（累积器挂 `window.__H` 上跨调用保留），
配合 `browser_batch` 一次打包 6–7 轮。实测 Build in Public 这样能稳定累积到 50+ 条、翻过 ~29000px。

**重抓后的真实密度（Build in Public 264.2K，两小时约 50 条样本）**：
- 个人打卡/励志/连续第 N 天：约 20 条 ｜ 增长与 SEO 技巧：约 8 条 ｜ 开发者工具与 agent 基建：约 8 条 ｜ 「帮我看看我的项目」：约 4 条
- **真正带终端用户痛点的：5–6 条，约 10–12%**。和 GitHub（13%）一档，低于 PH（53%），但**远不是零**。
- 痛点不是以「我需要一个 App」的形式出现，而是裹在**「我为什么做这个」的第一句**里，
  所以只看标题会全部错过，必须读正文。
