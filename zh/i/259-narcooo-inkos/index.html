面向长篇创作的智能体系统 — 长短篇小说、剧本、互动影游、IP…

面向长篇创作的智能体系统 — 长短篇小说、剧本、互动影游、IP 内容与多语言翻译，以 npm 包（@actalk/inkos）发布，AGPL 协议。

更新于 2026-07-28 · 来源 https://github.com/Narcooo/inkos · 英文版

Q：这条到底是什么？

一条把长篇故事撑住的 agent 流水线——情节状态、人物连续性、世界规则——从大纲一路推到一章又一章，同一套骨架还能出剧本、互动游戏和翻译。以 npm 包（@actalk/inkos）交付，得自己配模型 key。

Q：他为什么非要用不可？

按章拿钱、又不是 Node 开发者的网文写手。他拿到的是一份稿子——章节长度是他要的那个数，二十万字之后那个人物还认得出是同一个人。

Q：今天缺的到底是什么？

只有极客用得了，而且出来的东西还是流水账。真正想要它的人是写网文的，不是写 Node 的：要先装 Node 20+、手改 .env、挑模型供应商，才能写下第一句；侥幸装上的那批人报告章节字数失控、开局全都撞在同一个矿洞里。

Q：这一刀切在哪里？

别交付流水线，交付稿子。一键桌面安装、模型 key 预置，产品承诺只收窄到 issue 区证明已经坏掉的那一件事：把 20 万字撑住不崩、每章字数就是作者要的那个数。卖「不一样」而不是卖「量」——写到第一章就提示你又在写那个下矿开局。冷启动（中文）：inkos 自己的 issue 区，加番茄小说作者交流群与龙的天空论坛，写手自己在那里抱怨这几件事；冷启动（英文）：r/WritingWithAI 与 r/HFY 搜 lost the plot chapter。

Q：它最锋利的地方在哪？

上下文短的时候，跨几百章守住剧情状态与人物连续性根本谈不上。「agent＋外置状态」叠上便宜的长上下文阅读，才让一次 300 章的连跑变成一件你可以试着去接住的事。

Q：什么会杀死它？

「同质化」不是能打补丁的 bug，那就是让模型连写 300 章的必然结果，所有竞品都会撞上同一堵墙。同时番茄、起点这些平台正在给已经住在那里的写手直接发自家写作助手，后面还连着分发和稿费。让烂小说写得更快的工具，没人买。

Q：谁付钱，付的是什么？

按章拿钱的网文作者——每小时能出多少可读文字，字面上就是他的工资。月订阅，对标「一天多写一章」。

Q：最大的风险是什么？

需求是真的，但质量天花板归模型不归你；前沿模型一旦原生解决长篇一致性，中间这层编排就蒸发了。

Q：真人原话是怎么说的？

以下原声逐字摘自公开来源，未经改写： “大家没有发现这个问题吗？多开几本同类型的小说，比如：玄幻，你会发现主角开局要么下坑要么下矿要么捡垃圾，接着有个对他怀恨在心的npc张虎或者其他，再来一个对他好的老头吧啦吧啦，说实话去除人名，这些故事几乎一样。发散性严重不足。” — github-issue “AI味道还是有点，感觉写出来就像流水账，小说第一章字数正常，后面的字数无法控制” — github-issue “一开始我用很详细的和它说建立书， 他要啥给啥，然后总是建立失败， 说参数不对，引号问题，但是他又解决不了，就一直卡在这里。” — github-issue
