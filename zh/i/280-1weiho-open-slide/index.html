将代理生成的内容转化为令人惊叹的演示文稿，使用 open-slide

将代理生成的内容转化为令人惊叹的演示文稿，使用 open-slide。

更新于 2026-07-29 · 来源 https://github.com/1weiho/open-slide · 英文版

Q：这条到底是什么？

面向编码 Agent 的 React 幻灯片框架：用自然语言描述一份 deck，Agent 生成组件，open-slide 负责画布、缩放、排版和导出。

Q：他为什么非要用不可？

给 Agent 一种它真能写出来的幻灯片格式，排版和缩放问题已经替你解决。

Q：今天缺的到底是什么？

只有极客用得了：它是个 React 框架，交付物停在源码。真正需要一份 PPT 的是老师、销售、学生——他们要的是站在会议室里能打开的文件，而且上面得是公司规定的字体。

Q：这一刀切在哪里？

跳过框架，去做没有框架肯做的最后一公里：品牌锁定。拿公司现成的 PPTX 模板，学会它的母版，让 AI 生成的每一份片子一出来就已经长在里面——字体解析好、logo 放好、导出成同事能直接改的 PPTX。只干一件事：「我的片子看上去就是我们公司的片子」。冷启动（中文）：小红书、知乎上「PPT 模板 公司规范」的帖子与秋叶PPT 评论区，打工人在那里讲自己手动套版套到几点；冷启动（英文）：r/powerpoint 与 r/consulting 搜 brand template deck reformat。

Q：它最锋利的地方在哪？

Agent 已经会写 deck，却没有地方渲染——PowerPoint XML 极难生成，手写 HTML 幻灯片一缩放就崩。6k star 给的是底层管道而不是终端产品，说明开发者要的是一个可以直接输出到的幻灯片目标格式。

Q：什么会杀死它？

这是个功能不是公司。Gamma、Canva、微软都在发 agent 写片子，模板库和渠道本来就在他们手上；一个 MIT 框架一个版本就被吸收掉。真正会累积的资产属于握着助手的那一方，不属于握着渲染器的这一方。

Q：谁付钱，付的是什么？

框架是切入点，不是产品。钱在上一层：托管渲染、团队品牌与模板锁定、带浏览分析的分享链接，以及把 PPTX/PDF 导出做成付费 API——很多 Agent 产品都需要“导出成 deck”，但都不会自己做。Gamma 已经证明幻灯片工具撑得起订阅定价。

Q：最大的风险是什么？

它更像一个功能而不是一家公司。Gamma、Canva、微软都在加 Agent 生成 deck 的能力，而掌握助手入口的一方随时可以内置幻灯片输出，让框架变得多余。MIT 协议的管道层很容易被吸收，真正有护城河的托管层目前还不存在。
