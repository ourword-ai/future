nashsu/llm_wiki —— 跨平台桌面应用,把你的文档变成有组织、互相链接的知识库。

更新于 2026-07-27 · 来源 https://github.com/nashsu/llm_wiki · 英文版

Q：这条到底是什么？

桌面应用：读你指定的一个文件夹，自己把里面的文档织成一部互相链接的 wiki，而不是常见的「检索再回答」——它会写词条、会互相引用，于是你是在翻、在问，不是在搜。全程在本机跑，模型你自己接，云端或局域网 Ollama 都行。

Q：谁在用？他拿到什么成品？

用的人是自己电脑里堆了几百份文档的普通人：合同、说明书、课件、聊天导出。他拿到的是一本能翻、能问、能引用的本地维基，而不是一个搜索框。

Q：他为什么非要用不可？

硬盘里塞满 PDF、却再也找不到任何东西的人：研究生、单干的律师、接手了一堆公司文件的人。他拿到的是一本能翻的 wiki，不是一个还得他自己会问的聊天框。

Q：今天缺的到底是什么？

痛点是真的，但前五分钟只有极客过得去。真正需要它的是律师、研究生、硬盘里全是 PDF 的研究者——而 issue 区里挤满了这批人：模型配不上、文件夹选不了、局域网 Ollama 连不通，还没看到第一页 wiki 就走了。

Q：这一刀切在哪里？

卖前五分钟，不卖引擎。签名安装包＋自带能用的模型（或厂商替你出一把 key），一条「指一个文件夹，十分钟后拿到 wiki」的固定路径，并挑一个具体职业做首发切口——从卷宗审阅开始，那批文档在制度上就不许上云。冷启动（中文）：llm_wiki 的 issue 区，以及 #158 里用户自己拉起来的微信群——他们已经在自组织了；冷启动（英文）：r/ObsidianMD 与 r/LocalLLaMA 搜 ask my own documents offline。

Q：它最锋利的地方在哪？

检索增强一次只回答一个问题，语料本身仍然是一团。把整本 wiki 先写出来——词条、互链、一张能逛的地图——是长上下文便宜到可以把每份文档读两遍之后才谈得上的事。

Q：什么会杀死它？

Obsidian、Notion 和每一个笔记应用今年都在发同一个功能，而文档本来就在他们手里。33 位贡献者对 219 个未关 issue，这条线在往坏的方向走；「把我的文件夹变成 wiki」是个演示一次很惊艳、活不过第二周的东西。

Q：谁付钱，付的是什么？

文档在合规上不能上云的人：单打独斗的律师、会计、医生。桌面买断，对标「一下午在文件夹里翻找」。

Q：最大的风险是什么？

护城河是安装体验，而安装体验正是有钱的在位者一个版本就抄走的东西。

Q：真人原话是怎么说的？

以下原声逐字摘自公开来源，未经改写： “接 openai、kimi、minimax 的模型，全部都 analysis failed。实在是没招了，每个 api 都不行” — github-issue
