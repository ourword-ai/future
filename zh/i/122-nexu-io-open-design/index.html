nexu-io/open-design

nexu-io/open-design —— 开源的「Claude Design」替代品,本地优先的桌面 app:让你的编码 agent 变成设计引擎。

更新于 2026-07-27 · 来源 https://github.com/nexu-io/open-design · 英文版

Q：这条到底是什么？

本地优先的桌面应用，把 20+ 编码代理 CLI（Claude Code、Codex、Cursor…）变成设计引擎：原型、仪表盘、幻灯片、图片和视频，导出真实文件（HTML/PDF/PPTX/MP4），自带密钥。

Q：谁在用？他拿到什么成品？

本身已面向消费者；未被服务的切片是永远不会配 CLI 和 API key 的非技术用户。

Q：他为什么非要用不可？

今晚就要一份提案 PPT、一张户型图、一页房源单的人，要的不是设计工具，是那个文件。这是本板还放行的唯一一种「面向开发者」形态：AI 直接交出人能用的成品，而不是零件。

Q：今天缺的到底是什么？

给不会设计的人做设计工具，胜负仍取决于谁把代理包装得最好——但这个项目自己正在高速填补这个缺口：390 个贡献者外加自营付费 Cloud。

Q：这一刀切在哪里？

不正面打。开放的侧翼是垂直化：锁定一类人群（教师、房产中介、婚礼策划），配模板、托管、零密钥配置——这些正是横向开源工具刻意不做的部分。

Q：它最锋利的地方在哪？

今年之前，agent 会写代码，但交不出你能双击打开的 PPTX / PDF / MP4——你拿到的是一段对话，导出得自己来。真正吐出文件、并且用一个插口接住 20 多个 agent CLI，这才是变了的那一处。

Q：什么会杀死它？

你打不过一个有 390 名贡献者、有核心团队和自有变现的项目；任何'轻量克隆'起跑就落后三个月，对面每月还推 515 个提交。

Q：谁付钱，付的是什么？

向「想要 agent 驱动设计、又不愿把文件上传云厂商」的设计-研发团队,卖托管/团队版和企业授权。

Q：最大的风险是什么？

Figma 和模型厂商随时能接上同样的 agent-设计流程;光靠「本地优先」守不住,除非 agent→设计 的体验明显更好。

Q：要做多久？

不建议做，只作为能力信号存档

Q：证据来自哪里？

https://github.com/nexu-io/open-design
