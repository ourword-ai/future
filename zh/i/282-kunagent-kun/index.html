更新于 2026-07-29 · 来源 https://github.com/KunAgent/Kun · 英文版

Q：这条到底是什么？

Kun 把 需求澄清 → UI 设计 → 写代码 → 写文案 串成一个闭环，让这四件事之间的交接发生在同一个工作区里。

Q：谁在用？他拿到什么成品？

部分成立——承诺是给非工程师的，但当前形态是 agent 工作区，那是开发者的产物。真正普通人能拿走的是「规格访谈」这一片。

Q：他为什么非要用不可？

预算敏感、用国产模型的团队想要 Claude Code / Cursor 式的体验时，Kun 是为这条价格带原生设计的选项（5.5k★、26 位贡献者、月 758 次提交）。

Q：今天缺的到底是什么？

串起来不是稀缺的那一环；稀缺的是第一环——把一个模糊的「我想要」问成一份规格的那场澄清访谈。这条赛道上所有工具都默认你带着写好的规格来。

Q：这一刀切在哪里？

只留第一环，单独卖：一场澄清访谈，结束时给出一页规格——普通人可以拿它去找真人外包，也可以喂给任何 agent。冷启动：中文＝小红书/即刻「找人做个小程序被坑」的帖子；英文＝r/freelance 与 r/Upwork 里客户拿不出 brief 的讨论。

Q：它最锋利的地方在哪？

『需求澄清先行』的工作流 + 对高性价比国产模型的一等公民支持，而不是某个昂贵 API 的薄壳。

Q：什么会杀死它？

多段式 agent 工作区是 2026 年最拥挤的品类，绝大多数死在第二次交接：前面一个小误解，四步之后放大成一个没法用的产物。

Q：谁付钱，付的是什么？

切入点是价格敏感的中国开发者市场——按 DeepSeek 级 token 成本定价的托管团队版，正好卡在美国 Agent IDE 又贵又受限的空档。

Q：最大的风险是什么？

两头受挤：DeepSeek / 小米 / MiniMax 随时可以自带 Agent 工作台，需求澄清层本质是可复制的提示词；kun-agent.com 表明已在公司化——这个机会可能是他们的，不是你的。
