Yap：开源 macOS 菜单栏听写工具

Yap：开源 macOS 菜单栏听写工具，按住即说、松开即输入到任意应用，基于苹果本地 Speech 框架——无需下载模型、无需 API key、数据不出本机。

更新于 2026-07-29 · 来源 https://github.com/FrigadeHQ/yap · 英文版

Q：这条到底是什么？

按住快捷键说话，文字直接输入到当前聚焦的应用。它复用苹果内置语音栈，启动即用、离线可用，整个工具只是一层轻薄可改的 Swift 封装（HN 101 分、41 条评论）。

Q：他为什么非要用不可？

想要轻快、私密、免费的系统级听写，又不想为云服务或大模型下载付出延迟和隐私成本时，Yap 是最省事的选择。

Q：今天缺的到底是什么？

痛点击中了但解得不完美，而且隐私承诺有个洞：Intel Mac 上会回落到苹果服务器，README 那句「什么都不出本机」并没有讲清楚。另外只能用系统语言口述——这是 issue 区呼声最高的一条——等于把所有双语用户默默排除在外。

Q：这一刀切在哪里？

切口不是转写，是被苹果忽略的双语者：一种语言一个热键，一句话里中英混说不用切换任何东西，清理时知道哪些词是另一种语言里的专名。只做端上，并且明说——不要有静默的服务器回落。冷启动（中文）：小红书与 V2EX 上「语音输入法 中英混说」的帖子，双语用户在那里抱怨每个听写工具都逼你二选一；冷启动（英文）：Yap 自己的 issue 区（#2 与 #15 就是这个请求），加 r/macapps。

Q：它最锋利的地方在哪？

零配置本地听写：不用下 Whisper、不用 API key、没有云端往返——对臃肿听写工具的反击。

Q：什么会杀死它？

这是一家拿过融资的公司（Frigade）的副产品仓，窗口是他们自己的；而 macOS 自带听写就在设置里一个开关之外。对苹果 API 的薄封装，一个周末就能复刻，没有会累积的资产。

Q：谁付钱，付的是什么？

坦率说单靠它很薄。付费赛道（如 Wispr Flow，约 $12/月）卖的是 LLM 润色、自定义词表和多端同步；免费封装苹果免费 API 只能做获客入口，赚钱要靠上面那层打磨。

Q：最大的风险是什么？

苹果自带听写只隔一个设置开关，且每个系统版本都在变强；Yap 又是已融资公司 Frigade 的副产品——这个仓库是它的营销，不是别人能占的空位。
